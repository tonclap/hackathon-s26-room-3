Гарантия шва проверена машинно: все 60 `quote` найдены в исходниках обычным
`str.find`, без нормализаций. Модель предложила 66 кандидатов, код подтвердил
66, в файлы ушло 60 (потолок 20 на статью). В файл пишется подстрока
**исходника** по офсетам, а не строка модели, поэтому посимвольность не
зависит от поведения модели. Заодно код отбрасывает `kind` вне списка
контракта — модель пробовала выдавать свои (`pain`, `result`).

Заглавные факты числительными словами извлеклись с разобранными value/unit:
«ERP за три дня» (3 дня), «две недели» (2 недели), «все 40 микросервисов»
(40 микросервисов). Ровно то, ради чего не брал regex.

Замер, из-за которого не беру чистые regex: на три статьи 56 предложений с
цифрами и ещё 47 — с числительными словами («две недели», «за три дня»).
У статьи `97142` цифровых предложений всего 8, а заглавный факт «ERP за три
дня» — словами. Regex потерял бы почти половину фактуры.

Интерфейс — stdlib, без установки зависимостей:

```bash
python -m reels.extract reels/input/sostav-86369.md -o reels/out/86369/facts.json
python -m reels.extract reels/input/ -o reels/out      # все три разом
```

Если у лидера комнаты нет бинарника `claude` — режим `--no-llm` даёт
обеднённую выдачу (только предложения с цифрами), но не падает.
